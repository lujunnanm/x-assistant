# 神圣计划 4.0

一个总开关，协调 X 自动发帖、主动互动和通知回帖。浏览器扩展直接调用 DeepSeek，不需要本地桥接服务。

## 使用

1. 在 Chromium 扩展管理页选择“加载已解压的扩展程序”，加载本目录；升级时先停止旧协同，再重载扩展和 X 页面。
2. 打开扩展设置，验证并保存 DeepSeek API Key。密钥仅保存在当前浏览器扩展存储；输入框清空是隐藏密钥，不是删除。
3. 在已登录的 X 页面点击“启动协同”。自动关注、独立清理和上次／下次发帖时间在“更多”中。

安装、更新或浏览器重启后默认停止；运行中的普通页面刷新可恢复安全等待状态。文案、配图、处理记录、密钥及账号发帖排程不会因升级被清空。

## 当前规则

| 模块 | 规则 |
| --- | --- |
| 发帖 | 以文案库为参考，由 DeepSeek 生成短帖；保留相关话题、原有 `@grok` 和配图绑定；上传附件回读通过后才发送。成功后随机等待 **30–50 分钟**。 |
| 发帖恢复 | 按账号持久化上次／下次发帖时间。过期排程立即执行一次，不补发积压；未来排程继续等待。无已有排程时约 30 秒启动缓冲。 |
| 互动：开启关注 | 未关注、未关注、未关注、已关注作者轮换；回复→点赞 **5–10 秒**，点赞→关注 **5–10 秒**，帖间 **40–60 秒**。 |
| 互动：关闭关注 | 只处理可见曝光 **> 5000** 的帖子，不限制是否关注当前账号。回复→点赞 **3–5 秒**；帖间、跳过或可恢复失败后 **5–10 秒**。 |
| 目标搜索 | 支持主页和帖子搜索的热门／最新结果，保留搜索条件。六次滚屏无目标后刷新当前工作页。 |
| 通知回帖 | 每个窗口从顶部开始，优先处理当前已加载的最新评论；仅滚动 **24 小时内**、回复元数据明确指向当前账号的评论。排除自己、Grok、已确认回复。成功回帖后间隔 **3–5 秒**；AI 主动跳过或生成失败后间隔 **1 秒**。 |
| 自动清理 | 独立开关，与协同互斥；每 **10–30 秒**删除一条超过 24 小时、曝光 **< 50** 的本人原创帖。排除回复、转帖、文章、置顶、推广；必须收到平台删除回执。 |

### 三个模块如何切换

- 发帖优先；发送前 30 秒开始收回页面，等待当前动作安全结束。
- 互动没有“工作一小时休息半小时”的旧限制。
- **开启自动关注**：一次关注确认成功后，利用该次冷却处理回帖，最多 **40 秒**，同时不超过剩余冷却或发帖前 30 秒边界。没有另一个 10 分钟回帖计时器。
- **关闭自动关注**：每 **10 分钟**交接到回帖，直到没有候选、加载停滞／达到扫描上限，或发帖即将开始；可控结束后恢复互动。
- 到达工作窗口边界不接新发送；已经点击提交的请求继续核对回执。

### AI 与失败处理

- 按原帖／评论的主要语言回复；两类回复均不附加“交个朋友”“请回关我”等尾句。
- 规则在生成前读取并传入模型；区分 **AI 主动跳过**、**生成失败**、**目标更新**、**弹窗残留**、**提交结果未知**。
- 网络临时失败最多尝试 3 次，格式／内容校验失败最多 2 次；认证、余额、权限或配置错误立即停止并显示原因。重试只针对生成，绝不重试已提交的 X 操作。
- 旧版跨窗口 `batchSeen` 不再阻挡未发送评论。失败或主动跳过只在本窗口略过，下次仍可重新判断；本地成功记录继续去重。
- 可取消弹窗、未发送回复残留、保存草稿弹窗按规则取消／放弃并跳过。无法清理、账号变化或未知发送时停止，保留记录，不假装成功。
- 三次连续后台连接失败才停机；心跳不再排队等待 API 检查。停止原因可见并持久化，失联后须刷新页面再启动。

## 重构结构

无运行时第三方依赖，使用 Chromium Manifest V3、Web Locks、`chrome.storage.local` 和直接 DeepSeek 请求。

| 文件 | 职责／接口 |
| --- | --- |
| `scheduler-core.js` / `scheduler.js` | 纯调度策略 + 单会话状态机；`start/stop/beforePost/afterPost/replyDuringCooldown`。页面锁与回帖名额分离，避免交接死锁。 |
| `task-utils.js` | 墙钟超时、工作窗口、取消；`check/sleep/waitFor/bounded`。 |
| `x-dom.js` | X DOM 解析、回复元数据、精确身份匹配及重新定位；`rows/relocate/matches`。 |
| `reply-engine.js` | 互动与回帖共用的发送事务；`send({row,text,account,signal,deadline,patch,onBeforeSubmit,onConfirmed})`。先持久化提交意图，最终复核，再点击、等回执。 |
| `notification-policy.js` / `notifications.js` | 纯候选政策 + 每窗口独立扫描；`scan({account,runId,signal,yieldAt,cooldownSlot,show})` 返回完成／休息／让出原因及统计。 |
| `overlay.js` / `posting.js` / `cleanup.js` | 互动、发帖、独立清理驱动及悬浮窗。 |
| `background.js` / `state.mjs` | 授权、跨标签页归属、串行状态写入及兼容迁移。 |
| `posting-schedule.mjs` | 账号排程和幂等成功回执。 |
| `ai-client.mjs` / `deepseek-direct.mjs` / `ai-recovery.mjs` | 模型适配、规则加载、输出校验、脱敏错误分类和有限重试。 |
| `panel.*` | 密钥、文案／配图、已关注库和日志。 |

删除了不再使用的本地 Python 桥接与重复回复清理实现；保留 `bridge/*-rules.txt` 作为生成规则文件。

## 数据与密钥

直接调用 `https://api.deepseek.com`，模型为 `deepseek-flash`。规则、待回复文本或发帖参考会发送到 DeepSeek，API 费用由使用者承担。

密钥仅在当前浏览器 `chrome.storage.local` 中保存，不写入源码、不随文案导出，也不发送到其他服务。该存储不是系统钥匙串，不提供同等级加密保护。导出／导入文案会保留 `image` 字段，历史记录和未知提交证据不会因为更新被删除。
